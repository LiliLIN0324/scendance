# 幕景 Scendance · 活动场地工作台

当前前端版本：**v0.6.0 · 图纸重建预览**。上游项目的原始许可与来源继续保留。

v0.6.0 的运行、接口与验证边界见 [图纸／照片重建说明](../docs/floorplan-v2.md) 和 [验收记录](../docs/floorplan-verification.md)。下方 v0.3/v0.4 说明保留为历史背景，旧版功能限制以本次说明为准。真实模型与独立云环境尚未完成验收。

前端首版基于 PLAN 指定的 `threejs-sims-house-builder` 提交 `ab64647640a493657929246d62a2a37ebfc0ed42` 定向改造，使用 Next.js 静态导出、React、TypeScript、Three.js、Zustand。上游 MIT 许可见 [UPSTREAM-LICENSE](UPSTREAM-LICENSE)。原体育馆展示页仍在仓库根目录。

## 统一 Agent 入口

工作台 AI 功能集中在右下角 **Binggo Agent**，包含「场景策划 · DeepSeek」「模型与交付 · DeepSeek」和场景模板。策划接入异步 Agent run，展示进度并支持取消和原任务查询；活动需求、图纸与照片资料、尺寸核对仍在策划页折叠区。模型页提供桌、椅、柜台、地台、背景板和柜体的参数化需求入口，并保留材质调整、历史模型和交付导出。新建 HY3 文字、图片、纹理任务的控件已移除，历史任务只读取状态。

「明确指令直接应用」仅在服务端判定为明确普通操作时生效，可用画布撤销；模糊需求与探索性修改先预览。JEV 决策默认关闭，开启后比较三个候选并显示模型推荐概率，最终始终由用户选择确认；百分比不是真实成功率。场景、需求、修订号或编辑租约变化会使整组候选失效。任务编号按服务、用户、项目保存在本机，断线或重开只查询原任务，不自动重发付费生成。旧版入口记录保留在 [Agent 入口改造记录](docs/AGENT-ENTRY.md)。

## 运行

使用 Node.js 24.15+（建议 Node 24 LTS），在仓库根目录执行：

```sh
npm ci
cd frontend
npm ci
npm run dev
```

打开 `http://localhost:3000`。根依赖用于直接引用后端共享的 Zod 场景契约，前端目录有独立锁文件，不修改后端依赖。

生产构建与检查：

```sh
cd frontend
npm run typecheck
npm test
npm run build
python3 -m http.server 3018 --bind 127.0.0.1 --directory out
```

最后打开 `http://127.0.0.1:3018`。部署目录为 `frontend/out/`，不是仓库根的旧 `index.html`。所有 UI 字体使用系统字体，不依赖 Google Fonts。

## v0.3.0 新增

- 统一介绍页、工作台、助手的米白与植物绿配色；桌面优先显示 3D。
- 现场照片支持点击放大、删除、格式/体积/尺寸/数量校验和连续选图；介绍页往返保留输入，切项目隔离。
- 现场条件、风格、配色和氛围可编辑并随生成/助手文字请求提交；明确的物料替代也进入上下文。
- 助手携带当前需求、近期对话、最近提案说明；3000 字符上限不会截断必需条件，超限明确阻止发送。
- “场地”内提供三种真实灯光氛围选择，作用于 3D 且可撤销，沿用现有 Scene.lighting 保存。

- 图片入口定位为 **现场照片（选填）**：用于提供门窗、柱子、固定设施等场地资料；目前仅本机预览，不识别、不上传。尺寸仍在“场地”中填写，不承诺照片自动还原精确三维场地。
- AI 候选在三维画布显示临时差异，预览不保存、不进入历史；失效自动清除，正式应用仍走既有后端。
- 保守识别物料缺项、规格与形状差异；替代选择须明确确认，不将矩形桌冒充圆桌。

## v0.2.0 基础功能

- 登录介绍页，与工作台共用登录状态；可直接进入本地编辑。
- 图片和需求输入、Generate 按钮位于现有物料区，不新增栏目或灵感快捷按钮。
- 右下角助手提交文字布置/修改请求；提案经过确认后应用，生成期间的编辑不会被旧结果覆盖。建议仅以文字展示。
- 3D 场景采用真实灯光与阴影，读取后端已有 `neutral / warm / cool` 氛围字段，v0.3.0 在“场地”内增加对应下拉选择。
- 现场照片目前仅本机预览，不上传、不进行图片识别，刷新后需重新选择。

需求表单、照片与聊天记录仅在当前编辑器会话保留，刷新后不会恢复；介绍页往返保留，切换项目清空。实际场景仍按原有机制本地保存。

当前后端只支持基础沙龙/交流布局与有限修改指令，完整创意方案、帐篷等扩展物料、图片理解、通用助手对话需要后端支持。具体改动见 [最新后端需求交接（v0.3）](../docs/FRONTEND_V0.2_BACKEND_REQUIREMENTS.md)，版本记录见 [CHANGELOG](CHANGELOG.md)，本轮验证见 [v0.3.0 验收记录](docs/VERIFICATION-v0.3.0.md)。

## 当前可用

- 单层矩形场地、米制尺寸、后端 catalog 中的八类活动物料。
- 选择、拖动、旋转、调整尺寸、内置物件换色、备注、复制、删除、锁定、撤销/重做。
- 整体、俯视、客户观察角度与 2D 视图；“客户视角”只是相机预设，不是已发布客户页面。
- 本地自动保存；本版按产品界面要求隐藏物料区 JSON 导入/导出；真实 GLB 桌子样例可设定尺寸、复制、删除、刷新重开，保留原材质。
- 云项目弹层、Auth 登录、工作室/项目列表、创建/打开项目、获取/续期/释放编辑权、版本校验保存与私有模型授权请求均已接线。
- 未配置后端时只使用本地模式，云项目不会显示伪造的保存成功。
- `/auth` 是唯一登录页面，统一支持登录、注册、六位邮箱验证码及本地体验；`/introduction` 展示首页的“进入场景”和云项目入口均指向这里。`/` 保留工作台，匿名访问会转到 `/auth`，本地体验使用 `/?local=1`。登录后保留安全返回目标，密码找回继续使用独立流程。

本机未配置真实云端，因此本轮只证明本地编辑和接口契约通过测试，**没有证明真实云端、双账号交接、第三方生成或手机真机闭环**。

后续合并联调已补充真实 HTTP + 后端处理器 + PostgreSQL 测试库验证，以及测试账号在浏览器中的保存、刷新重开与交接。Auth/Storage 在该环境使用显式测试实现，真实 Supabase 云端仍未验收。复现方法与结果见 [前后端联调报告](../docs/INTEGRATION.md)。

GPT 接入由成员 2 按 [GPT 核心链路交接](../docs/FRONTEND_V0.2_BACKEND_REQUIREMENTS.md#gpt-handoff) 实施；前端沿用 proposals 接口，无供应商专属改动。模型切换不会解除现有模板与 1–40 人限制。

## 部署后配置

复制 `frontend/.env.example` 为 `frontend/.env.local`，在本机填写：

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-public-anon-or-publishable-key
```

仅放公开 anon / publishable key；不要放 service-role、模型 API key、worker secret。公开配置在构建时写入前端，修改后要重启开发服务或重新构建。账号密码在登录框输入，Auth access/refresh token 只在内存，刷新后重新登录；本地草稿保留。

B 按 [后端部署说明](../docs/DEPLOYMENT.md) 部署、迁移并准备工作室账号；将实际前端 Origin 加入后端 `ALLOWED_ORIGINS`。`http://localhost:3000` 与 `http://127.0.0.1:3018` 是不同 Origin，应按实际地址配置。

验证顺序：登录 → 把当前画布创建为项目 → 获取编辑权 → 移动物件 → 保存 → 刷新、登录并打开项目 → 检查数据 → 释放编辑权 → 第二个账号接手。获取编辑权始终采用服务端最新场景并清空旧撤销历史；保存失败、断网或版本冲突不会丢弃当前草稿。
