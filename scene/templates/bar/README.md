# 琥珀间 · 酒吧场景模板

一套暖琥珀、胡桃木与酒红配色的静态酒吧概念场景。室内设计尺寸为 **12 × 9 米，108㎡**；场景不含人物、人数调节或活动阶段切换。

布局包含镜面背吧酒架、L 形服务吧台、6 张独立高脚凳、3 组酒红卡座与石材圆桌，以及水槽、冷藏柜、制冰机、收银终端、搅拌机、双龙头和杯具陈列。吊灯、壁灯与背吧灯光形成暖色氛围。

## 本地预览

在本目录运行：

```sh
python3 serve.py
```

打开 `http://127.0.0.1:8779/`。预览通过 `GLTFLoader` 读取本地 **`./bar.glb`**，依赖本目录内的 Three.js 文件。完整 GLB 的纹理已内嵌，不需要外部模型或纹理下载。请通过本地 HTTP 服务打开，不能直接双击 HTML 文件运行。

预览支持整体、正交俯视和场内视角。整体与场内视角可拖动旋转；各视角可缩放，并可分别切换外墙与顶部显示。默认显示外墙、隐藏顶盖。显示开关只影响当前预览；下载的 GLB 保留完整场景。预览用于查看静态布局，不包含人流仿真。

## 场景与编辑边界

模型以米为单位、Y 轴向上。12 × 9 米指设计地板范围；墙厚、装饰与顶部构件可能超出该范围，因此模型整体包围盒不等于净使用面积。

根节点为 `Bar_AmberRoom_12x9`，主要分组如下：

| 分组 | 内容与用途 |
|---|---|
| `Bar_Structure` | 地板、墙体及建筑构件；外墙保留 `Bar_Walls` 子组 |
| `Bar_Furniture` | 吧台、座椅、桌台等可单独选择的家具 |
| `Bar_Equipment` | 陈列、酒吧设备和细部道具 |
| `Bar_Lighting` | 灯具及灯光相关构件 |
| `Bar_Roof` | 顶部构件，便于切换俯视与封顶效果 |

独立家具按 `Bar_Role_001` 的形式命名，`Role` 表示物件用途。导入编辑器后，可选中对应物件的父节点进行整体平移、旋转或缩放；桌腿、坐垫等子网格保留为物件内部构件。改变分组位置不会自动重排相邻家具或更新通道，拆分导出为单件物料时还需单独设置原点、尺寸与缩略图。

部分物件共享材质与几何数据。仅修改一件的颜色、材质或网格形状时，建议先克隆该物件的 `material` / `geometry`，避免同时影响其他物件；物件父节点的位置和旋转可独立修改。

尺寸、布局和材质均为概念设计假设，不来自现场测绘。模型不能作为现场安全、消防、承载、电气或施工认证；家具和通道仍需按实际场地复核。

## 文件与正式接入

- `bar.glb`：可独立导入 glTF 工具的完整场景，纹理内嵌。
- `bar-template.zip`：包含模型、预览与来源说明的模板交付包。
- `index.html`、`app.js`、`style.css`：本地交互预览。
- `model.js`、`scene-kit.js`：程序建模、场景参数与构建辅助代码。
- `template.json`：本地模板元数据。
- `assets/catalogue.json`：原创构建来源、依赖说明与空的外部资产清单。
- `previews/`、`validation/`：渲染截图和对应验证记录；验证结果以实际生成文件为准。

修改建模代码后，打开 `http://127.0.0.1:8779/?build=1`，等待场景构建完毕，再点击“保存酒吧模板”。本机 `serve.py` 会把完整模型写回本目录的 `bar.glb`，包含外墙与顶盖。随后重新打开普通预览地址，检查导出的文件。保存模型后，旧截图、校验结果及 ZIP 不会自动更新，需重新生成。

在酒吧目录执行格式与模型检查：

```sh
node validation/validate.mjs
```

验证脚本复用工作区已有的 `scendance-frontend/node_modules/gltf-validator`。移动模板目录后，可用环境变量 `GLTF_VALIDATOR_MODULE` 指定可用的 `gltf-validator` 模块路径；该依赖仅用于校验，不是预览页面的运行依赖。

本地 `serve.py` 将本目录文件映射为静态 HTTP 资源，模型与元数据分别通过 `GET /bar.glb` 和 `GET /template.json` 读取。

建议正式产品接入时放入 `scene/templates/bar/bar.glb`，并在同目录配置 `template.json`，由模板选择入口加载；正式后端可分别提供静态路由 `/scene/templates/bar/bar.glb` 和 `/scene/templates/bar/template.json`。目前此独立模板**尚未接入正式产品，也未写入资产注册或上传 API**。

`bar.glb` 是带建筑、家具与设备的完整场景，**不能直接当作单物料提交到物料上传 API**。若要登记单件家具，应先按独立物件分组拆分，再按物料接口的结构与尺度要求处理。

## 模型验证结果

2026-10-03 导出的 `bar.glb` 为 **4,134,000 字节（约 3.94 MiB）**。Khronos glTF Validator 检查为 **0 错误、0 警告**，另有 480 条信息级提示，完整保留在 `validation/gltf-validation.json`。

模型含 937 个唯一命名节点、872 个网格实例、55,242 个三角形实例、30 种材质及 8 张内嵌图片，外部资源引用为 0。42 个独立可编辑对象均与 inventory 记录一一对应，包含建筑、家具、设备和灯具；没有访客、工作人员节点或动画。实际光源共 6 个。

20 个声明的地面占位矩形均在 12 × 9 米设计范围内，没有未声明的相互穿插；L 形吧台的两个连续分段在转角处有意相接，单独记录在允许交叠列表。矩形并集占地约 27.23㎡，只用于概念几何检查，不等于净可通行面积或现场容量判断。世界包围盒为 12 × 3.56 × 9 米（含地板厚度）。

模型细目见 `validation/model-inspection.json`，占位记录见 `validation/layout-check.json`。浏览器操作结果另见 `validation/browser-validation.json`。

浏览器已实际完成 9 项检查：独立 GLB 载入、整体 / 俯视 / 场内视角、拖动旋转、滚轮缩放、外墙隐藏、顶盖显示及控制台检查，全部通过，未出现控制台错误或警告。三张预览截图均来自当前导出的酒吧模型。
