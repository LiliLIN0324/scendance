## 实际协议与草案差异

任务包 `CONTRACTS.md` 中的 v2 是 DRAFT 建议，不能作为已经实现的接口。前端直接导入 B 的 `Scene`、`sceneSchema`、`catalog`，没有另造共享 API 协议，也没有把后端升级为 v2。S01 后续应由 A/B 对齐文档与实现；本次只在前端边界做转换。

| 项目 | 后端实际 v1 | 编辑器与本次处理 |
| --- | --- | --- |
| 物件字段 | `objects`、`size`、`rotation` | 草案的 `instances`、`dimensions`、`rotationY` 不直接传给服务端 |
| 长度 | 场地、位置、尺寸统一为米 | 编辑器也使用米，不乘除 1000；例如 10 毫米写作 `0.01m`，不将 `10` 当米传入 |
| 平面坐标 | 场地 X 为 `0..width`，Z 为 `0..depth` | 编辑器原点在中心：`x = backend.x - width / 2`，`z = backend.z - depth / 2`；保存时反向平移 |
| 场地尺寸 | `venue.width / depth / height` | 编辑器 `layout.width` 是宽，`layout.height` 是平面深度，`floor.height` 才是竖直高度 |
| 旋转 | 角度制，正角从 +X 转向 +Z | Three.js 绕 Y 正转方向相反：`editorRadians = -backendDegrees * Math.PI / 180`；反向保存对应取负换算 |
| 主要出入口 | `venue.entrances` 中的 ID、`position`、`width` | 使用带 `venueEntranceId` 的锁定门标记展示；保存时回到 entrances，不混入 objects |
| 资产 | 稳定 `assetId` | 授权 URL 仅用于加载，不写入 `scene.save`；本地样例没有云 assetId，阻止直接云保存 |
| 其他字段 | `materialId`、`notes`、`locked`、`camera`、`lighting` | 在本地状态和往返转换中保留；来源信息不擅自加入后端 Scene |

30° 非方形物件测试对照了后端角点和 Three.js 旋转方向，避免仅靠 0° 或正方形往返测试掩盖符号错误。适配器也保留 `assetId`、颜色、备注和锁定等信息，本地序列化覆盖新增字段。

本版不能无损处理的输入会在替换当前画布前拒绝：多边形场地、云端底图、超出编辑器尺寸范围的物件等。云保存同时拒绝未支持的多层、建筑结构、镜像、本地未归档资产和缺失出入口，防止丢弃这些信息后保存。当前入口范围仍是矩形；这不代表 PLAN 的底图和简单多边形要求已取消。

底图/多边形的适配缺口是：人工尺寸标定与轮廓编辑 UI、持久化映射、地板/边界渲染、出入口定位与拖放边界约束需要共同改造，再与 B08 往返验证。现有矩形布局不能证明这些部分已可用。详细成本估算与最小技术验证仍须在 A08 开始前补齐，不据此宣布 A01 全部完成。

## 运行与检查

从独立 clone 的仓库根目录运行，使用 Node.js 24.15+：

```sh
npm ci
cd frontend
npm ci
npm run dev
```

生产预览使用静态导出目录：

```sh
cd frontend
npm run typecheck
npm test
npm run build
python3 -m http.server 3018 --bind 127.0.0.1 --directory out
```

两段命令分别从仓库根目录开始。部署目标是 `frontend/out/`，不是旧根目录 `index.html`。构建命令成功不等于已经部署到外网。
