# 场景规划 Agent · 项目规划与 PRD v0.2

## 1. 产品定位与交付目标

**面向小型活动策划执行工作室的三维场景协作 Web 应用：用 AI 和内置物料快速形成活动方案，让团队共同完善布置，并向客户交付可自由查看的三维场景。**

需求依据为[飞书 PRD](https://my.feishu.cn/wiki/IpFNwYdoci5vc9kLRVXcp8Oan4b)及本轮确认。本文独立重写，飞书保持不变。旧方案中的二维教室定位不再沿用；现有私人派对 Figma 原型仅供交互参考，[原型说明](</Users/lwc/Documents/ChatGPT/场景规划Agent产品开发/prototype/README.md>)也明确尚未实现真实三维、AI、持久化和下载。

### 已冻结的产品决策

| 项目 | 首版决定 |
|---|---|
| 首批客户 | 小型活动策划执行工作室 |
| 主要案例 | 小型黑客松/工作坊/竞赛 |
| 使用设备 | 电脑浏览器编辑；手机、电脑浏览器查看 |
| 访问地区 | 中国大陆 |
| 空间精度 | 场地和物料基本尺寸准确，先支持多边形矩形单层场地 |
| 视觉风格 | 精致低多边形三维，编辑与交付使用同一场景 |
| AI 能力  | 生成初稿，以及有限的场景修改 |
| 团队协作 | 多人轮流编辑，同一项目同一时刻一人持有编辑权 |
| 客户交付 | 无需登录的只读链接，可以撤销 |
| 物料准备 | 根据场景自动汇总名称、数量、尺寸和备注 |
| 三维生成 | 真实接入单物件生成；允许提前生成后现场展示 |
| 生成物件用途 | 场景展示道具，可整体移动、旋转、调整尺寸 |
| 开发约束 | 两人主要开发，48 小时演示，试验总预算不超过 300 元 |
| 账号范围 | 演示预置真实账号；开放注册、邀请成员放到后续 MVP |
| 后续节奏 | 按验收里程碑推进，不承诺日历日期 |

**核心用户价值假设：** 减少“客户脑中的效果、设计师的方案、执行人员理解的布置”之间的信息差。后续通过真实工作室任务验证，暂不宣称已降低成本或提高成交率。

付费方假设为工作室负责人。后续优先验证“工作室订阅＋三维生成额度”的收费方式；首版不开发支付系统。

## 2. 功能需求与使用流程

### 核心流程

创建项目与场地 → 描述活动需求 → AI 生成可编辑初稿 → 人工调整 → 补充生成物件 → 团队交接编辑 → 核对物料表 → 发布客户只读版本。

### 48 小时必须交付

| 模块 | 具体行为 | 完成标准 |
|---|---|---|
| 登录与项目 | 两个独立团队账号；创建、命名、打开项目 | 刷新后仍能从云端打开自己的团队项目 |
| 场地设置 | 输入平面图 + 输入长、宽、高；设置主要出入口 | 米制统一，场景比例与输入一致 |
| 三维库公共库推荐 | 根据活动主题、场地和已选物料，从现有素材网站调用可用模型并推荐可加入场景的三维物件 | 推荐列表显示模型名称、缩略图和来源；用户可预览、选择并加入场景，加入后可继续编辑且保存、重开一致 |
| 三维编辑 | 添加、选择、拖动、旋转、改尺寸、换色、复制、删除、锁定、撤销/重做 | 操作真实改变场景数据，保存后保持一致 |
| 内置物料 | 椅子、桌子、签到台、背景板、展架、隔断、地毯、装饰道具 | 每种有稳定编号、默认尺寸和可辨认外观 |
| AI 初稿 | 理解主题、人数、场地、分区和色系，组合内置物料 | 生成对象均可继续编辑 |
| AI 修改 | 增删、移动、旋转、换色、替换物件 | 显示修改提案，用户确认后应用 |
| 三维物件生成 | 提交描述、查看任务状态、预览结果、设定尺寸、加入场景 | 至少一件真实 API 生成物件完成保存、重开 |
| 轮流编辑 | 获取、续期、释放编辑权；显示当前编辑者 | 第二位成员不能覆盖第一位成员的有效编辑 |
| 自动物料表 | 按物料与规格汇总数量，显示尺寸与备注 | 与当前场景快照一致 |
| 客户查看 | 发布独立版本，手机可旋转、缩放、切换预设视角 | 无编辑权限；不展示未发布草稿 |
| 分享撤销 | 项目负责人撤销链接 | 后续场景访问请求被拒绝 |

其中，“单物件三维生成”从飞书 P1 提前纳入演示必做项。其余 P1 保留到后续里程碑。

### 页面与交互

**项目页：** 项目名称、缩略图、更新时间、当前编辑者、新建入口。

**编辑工作台：**

- 顶部：项目名、保存状态、编辑权状态、发布按钮。
- 左侧：物料库、个人生成素材、物料汇总。
- 中间：三维场景，提供整体、俯视、客户视角。
- 右侧：选中对象属性与 AI 面板。
- 生成任务在独立区域展示，不阻塞已有场景操作。

**发布面板：** 预览发布版本、生成链接、复制链接、撤销链接。再次发布产生新版本；旧链接继续指向原版本，直到被撤销。

**客户查看页：** 场景、方案名称、版本时间、视角控制。手机优先展示场景，隐藏编辑工具和内部备注。

### 必须明确的行为边界

- 首版物件以地面落点布置；吊挂、复杂叠放、多层场地不进入演示范围。
- 物料尺寸表示录入或设定的尺寸。生成物件通过包围盒归一化后设定整体大小，不承诺真实制造结构。
- 场地边界和基本重叠可以提示，但不将这些提示包装成消防、承重或完整施工校验。
- 生成物件在物料表中标记“概念道具，实物待确认”，不编造供应商、库存或价格。
- AI 提案不直接覆盖画布；人工编辑之后返回的旧提案必须失效。
- 三维生成失败时，用户可以继续使用内置物料；替代物料不能被显示为生成成功。

### 编辑器底座的具体改造

首选固定到已核查的提交 [`ab64647640a493657929246d62a2a37ebfc0ed42`](https://github.com/ch-bas/threejs-sims-house-builder/tree/ab64647640a493657929246d62a2a37ebfc0ed42)。

保留其 **Next.js＋React＋TypeScript＋原生 Three.js＋Zustand**，以及现有交互和历史记录。隐藏屋顶、多楼层、街区、天气、游戏预算等无关入口，替换为活动物料和项目工作台。

必须新增的内容：

1. **云项目与权限。** 上游没有账号后端；其原分享把场景编码进 URL，不具备客户只读、撤销和版本隔离能力。
2. **活动物料契约。** 添加物料 ID、资产 ID、规格和来源；同时修改序列化白名单，避免保存后新字段丢失。
3. **通用 GLB 导入。** 上游已有 GLB 导出，但没有通用生成模型导入，需要补加载、尺寸归一化、材质保留和资源释放。
4. **受控 AI 操作。** 对接有限命令，不能直接把底层全部状态操作暴露给模型。

这些缺口已通过[分享实现](https://github.com/ch-bas/threejs-sims-house-builder/blob/ab64647640a493657929246d62a2a37ebfc0ed42/components/room-organizer/lib/share.ts)、[场景解析](https://github.com/ch-bas/threejs-sims-house-builder/blob/ab64647640a493657929246d62a2a37ebfc0ed42/components/room-organizer/lib/schema.ts)和[物料构建器](https://github.com/ch-bas/threejs-sims-house-builder/blob/ab64647640a493657929246d62a2a37ebfc0ed42/components/room-organizer/three/furniture-builders.ts)核查。

## 4. 数据、接口与关键实现路径

### 数据模型

采用少量明确的业务对象：

| 对象 | 最小职责 |
|---|---|
| 工作室与成员 | 工作室 ID、用户 ID、负责人/编辑成员角色 |
| 项目 | 工作室归属、名称、当前场景、云端版本号 |
| 场景 | `schemaVersion`、场地、物件实例、相机、灯光预设 |
| 物件实例 | 稳定实例 ID、物料/资产 ID、位置、旋转、尺寸、颜色、锁定状态 |
| 资产 | 所有人、来源、存储路径、格式、尺寸信息、授权记录 |
| 生成任务 | 内部任务 ID、提供商任务 ID、状态、成本记录、结果资产 |
| 发布版本 | 不可变场景快照、对应物料表、资源清单 |
| 分享与编辑租约 | 分享令牌哈希、撤销状态；编辑会话、租约代次、到期时间 |

统一采用米制。领域数据使用明确的 `width/depth/height`，由适配层转换为上游字段，避免上游部分 `height` 实际表示平面深度造成混淆。

个人生成素材默认归生成者所有；加入团队项目后，该项目成员和获授权的客户可以查看项目引用的资产，但不能浏览生成者的整个个人素材库。

### 最小接口

| 接口 | 输入与输出 |
|---|---|
| 项目创建/读取 | 场地、项目名称 → 项目 ID、场景、版本 |
| 获取/续期/释放编辑权 | 项目、编辑会话 → 租约与到期时间 |
| 保存场景 | 场景、租约、`expectedRevision` → 新版本或冲突 |
| AI 提案 | 当前场景、需求、云端/本地版本 → 修改提案、说明、校验结果 |
| 创建生成任务 | 物件描述、请求幂等键 → 内部任务 ID |
| 查询生成任务 | 任务 ID → 真实状态、错误或资产预览 |
| 发布方案 | 已保存版本 → 发布版本与分享链接 |
| 查看/撤销分享 | 分享令牌或分享 ID → 只读快照或失效状态 |

静态页面使用 `/projects/`、`/editor/?project=…`、`/view/#…`。不依赖静态构建时不存在的动态项目路由。

### AI 初稿与修改

首版采用两套活动布局模板：坐席沙龙、开放交流。AI 选择模板、物料数量、分区和配色，代码生成并检查坐标。

修改命令限制为添加、删除、移动、旋转、换色和替换。整个流程为：

1. 读取当前场景、选中对象、锁定对象和可用物料。
2. 调用模型生成结构化提案。
3. 校验物料 ID、动作、尺寸、场地边界及锁定状态。
4. 必要时进行一次修复请求；仍不合法则返回具体问题。
5. 用户预览确认后，一次性应用为一个可撤销操作。

同时检查云端版本和本地场景版本。生成期间发生人工编辑或编辑权变化时，旧提案不得应用。完整系统提示词随实现保存为可审阅文档。

### 轮流编辑与保存

- 同一项目只允许一个编辑会话持有租约；同一用户的两个标签页也视为两个会话。
- 默认租约 90 秒，每 30 秒续期，可主动保存并交接。
- 数据库在同一事务内检查成员资格、有效租约和版本，再保存并递增版本号。
- 失去租约或发生冲突时保留本地草稿，禁止自动覆盖云端。
- 重新获得编辑权后加载最新场景，重置撤销历史。
- 浏览器不能通过另一个直接写表入口绕过这些检查。

### 三维生成与模型接入

采用“提交任务—查询状态—归档资源”的异步流程，Edge Function 不持续等待模型生成。提供商任务 ID 和状态存入数据库，页面重开后可继续查询。后台定时检查未完成任务，及时归档结果，避免临时下载地址过期。

状态统一为：

`待提交 → 已提交/处理中 → 归档中 → 可预览 → 已加入`

失败、结果不合格、提交结果未知分别显示。提交超时不自动重复创建付费任务。

生成完成后：

- 保存 GLB 到自有私有存储，不长期引用提供商临时地址。
- 校验可加载性、纹理、文件体积和模型复杂度。
- 将模型底部对齐地面、中心归一化，让用户指定整体尺寸。
- 保留原始纹理；实例复制和删除不得损坏共享资源。
- 预览确认后才加入场景；单次加入可以撤销。

首版默认单个 GLB 不超过 10MB，演示场景控制在 50 个物件以内。超限结果提示更换或优化，不强行加载导致手机崩溃。

### 客户分享与访问

分享引用不可变发布版本，发布时同时冻结场景和物料汇总。分享令牌随机生成，服务端保存哈希，每次请求检查撤销状态。

撤销后立即拒绝新的场景及资源授权请求。已签发的短期资源链接可能在到期前继续有效，已下载内容不能收回；资源链接默认有效期 5 分钟。[Storage 下载机制](https://supabase.com/docs/guides/storage/serving/downloads)

## 5. 实施排期、预算与验收

### 48 小时冲刺

| 时段 | 开发者 A | 开发者 B | 阶段出口 |
|---|---|---|---|
| 0–4 小时 | 固定底座、构建、验证尺寸与 GLB 加入/重开 | 配置账号、云项目；完成一次真实生成调用 | 底座、账号、真实生成和大陆网络均有证据 |
| 4–16 小时 | 活动物料、工作台、场地、模型导入 | 项目保存、成员隔离、编辑租约 | 两账号能够交接同一云项目 |
| 16–28 小时 | AI 提案预览、撤销、物料汇总 | AI 接口、生成任务、归档、费用限制 | 初稿与生成物件都能保存重开 |
| 28–36 小时 | 手机查看、预设视角、加载状态 | 发布快照、分享与撤销 | 客户交付闭环完成 |

### 必须通过的验收

| 场景 | 通过标准 |
|---|---|
| 真实演示闭环 | 品牌沙龙项目完成初稿、人工修改、生成物件加入、交接、发布和手机查看 |
| 账号隔离 | 非成员不能读写项目；客户链接不能调用编辑接口 |
| 编辑冲突 | 第二会话、过期租约、旧版本保存均无法覆盖当前场景 |
| AI 变更保护 | 锁定对象不被修改；人工编辑后返回的旧提案被拒绝；一次应用可单步撤销 |
| 生成真实性 | 保留真实任务记录和 GLB；模型能移动、旋转、改整体大小、保存重开 |
| 模型生命周期 | 复制生成物件后删除其中一个，另一个仍正常显示 |
| 物料一致性 | 添加、删除、复制、改规格后汇总正确；发布版本与物料表对应 |
| 分享撤销 | 撤销后的新访问被拒绝；旧发布链接不泄露后来修改的草稿 |
| 故障恢复 | 模型失败不丢场景；刷新恢复云项目；网络中断明确显示未保存状态 |

| 构建与测试 | 类型检查、现有测试、关键新增测试、静态构建及部署后直接刷新链接通过 |

性能验收目标：示例场景在指定测试电脑和手机上可连续旋转、缩放，目标不低于 30 FPS；首次可交互时间目标不超过 10 秒。以上是待验证目标，不是已有测试结果。

演示可以使用提前真实生成的资产，并明确标注“已生成案例”。本地备用场景用于展示恢复，不替代云协作验收。

### 后续 MVP 里程碑

**M1：真实团队试用。** 开放注册、邀请和移除成员、密码恢复、项目复制、版本恢复；完善费用限制与大陆网络体验。邀请 3 家工作室各完成一个真实项目，记录求助次数、修改轮次和客户理解问题。

**M2：完成其余 P1。** 增加个人素材管理、物料参数化 DIY、海报贴图生成，以及工程 JSON、PNG 效果图和 PDF 方案导出。“设计稿”默认指这些方案交付文件；CAD、施工图和网格建模暂不纳入。
