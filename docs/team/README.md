## 四个人怎么排

| 角色 | 推荐人选 | 主责 | 第一份交付 |
|---|---|---|---|
| A：三维前端 | **Sandraddd（已确认）** | 编辑器、平面图标定/轮廓、GLB 预览加入、物料表、手机页 | A01：底座构建与 GLB 保存重开 |
| B：后端、AI 与集成 | 擅长接口、数据、调试和部署的人 | 账号、云保存、编辑权、AI、真实生成、公共模型接入、发布与合并 | S01：契约和目录归属；B01：服务可行性 |

| D：测试与路演 | 另一位懂布置且需要上台的人 | 布置可落地性、双账号/手机/异常测试、讲稿、录像和排练 | D01：设备与网络记录；随后 D02 测试矩阵 |

四个角色不是技能互斥：如果懂布置的人同时最擅长开发，优先保证 A/B 的开发能力，再安排产品和测试职责。D 主讲，C 操作演示，A/B 做技术保障。成员 GitHub 用户名未提供时保留为空，不把仓库拥有者或当前登录者自动当成某个角色。

## 本次演示流程

上传平面图并标定尺寸 → 描绘单层场地与主要出入口 → AI 生成布局初稿 → 人工调整 → 加入公共库推荐模型 → 加入一个真实生成道具 → 两账号交接编辑 → 核对物料表 → 发布手机只读版本 → 撤销链接。

建议演示使用 **16 人、4 个小组** 的工作坊/小型黑客松，控制在 PLAN 的 50 物件以内；矩形样例可沿用 10×8×3 米，另备简单凹多边形样例。这些是待 C01 确认的建议，不是真实测量结果。

最新 PLAN 的前后章节存在旧案例未同步和“多边形矩形”的歧义。本包按“矩形或简单单层多边形、上传图后人工标定和描边”拆任务，不承诺自动识图、CAD 解析或三维重建。C 在 C01/G0 记录团队决定，详见 [分工变化](PLAN-CHANGES.md)。

## 每个人怎么开工

1. 从唯一远程 [LiliLIN0324/scendance](https://github.com/LiliLIN0324/scendance) 克隆自己的副本，使用自己的本地路径。
2. 阅读 [GitHub 操作说明](GITHUB.md)、[协作规则](COORDINATION.md)；A/B 先对齐 [契约草案](CONTRACTS.md)。
3. 将 [prompts](prompts/) 中对应角色提示词交给自己的 AI。`runtime.repository_root` 的 `.` 指各自仓库根目录，不是某位成员的绝对路径。
4. A 做 A01，B 做 S01/B01，C 做 C01，D 做 D01。前四小时以真实证据检查可行性；新增功能使原排期更紧，G0 必须据实重排。
5. 每项任务从最新 `main` 开短分支，通过 PR 交付，附 [交接报告](HANDOFF_TEMPLATE.md)。B 汇总 TASKS.json，D 独立复验运行结果。
